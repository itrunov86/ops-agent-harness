# Переезд на новое место работы

Всё, что зависит от организации, — в одном конфиге и в вашей базе знаний. Harness переносится за вечер.

## Что взять с собой, а что оставить

| Берёте | Оставляете |
|---|---|
| Этот репозиторий (форк на GitHub) | Базу знаний прежней работы — это знания компании |
| Свои правки скиллов, сделанные в форке | Командные шаблоны компании, токены, конфиги MCP-серверов |
| Привычки: журнал задач, kb-compile, ретро | Память агентов (`~/.claude/…/memory`) с фактами о прежней инфраструктуре |

## Чек-лист

**1. Машина** (15 минут)

```bash
python3 --version                    # 3.11+
git clone https://github.com/<you>/agent-harness ~/Projects/agent-harness
cd ~/Projects/agent-harness
```

Установите Claude Code и/или Codex.

**2. Конфиг** (10 минут)

```bash
./harness init
```

Нужно знать: короткое имя организации, где будут база знаний и папка чатов, префиксы ключей задач в трекере
(`PLAT`, `SRE`…), проект и тип для новых задач, свой логин в трекере, адреса трекера, вики и чата, каналы алертов.
Чего не знаете — оставьте пример и поправьте позже в `~/.config/agent-harness/config.toml`.

**3. Установка** (5 минут)

```bash
./harness install --dry-run
./harness install
./harness doctor
```

Новая база знаний создастся из шаблона. В Codex — `/hooks` → доверить.

**4. Глоссарий** (30 минут, самое ценное)

В `<kb_root>/navigation/glossary.md` впишите сервисы новой компании и их внутренние названия, как их называют
коллеги. Удалите пример `payments` и хаб `services/Payments.md`, заведите хабы для 3–5 главных сервисов.

**5. MCP-серверы** (зависит от компании)

Пройдите по таблице возможностей в [mcp.md](mcp.md): какие системы есть (трекер, вики, чат, метрики, логи,
git-хостинг), какие MCP-серверы для них разрешены политикой компании. Начните с трекера и метрик. Подключите
поиск по базе: команду печатает `install`.

**6. Права агента** (15 минут)

В `~/.claude/settings.json` (`permissions`) разрешите чтение (`kubectl get`, `terraform plan`, `argocd app diff`…),
пишущие команды — в `ask`. Если доступ к облаку идёт через ключи — сделайте обёртку, которая берёт их из Keychain
(см. [security.md](security.md)).

**7. Командные шаблоны** (по мере надобности)

`team-skills/` — заготовки. Перед первым постмортемом или отчётом спринта заполните `defaults.yaml` скилла:
пространство вики, поля трекера, метки, структуру страниц под принятую в команде. Если в компании есть свои
шаблоны — сделайте скилл по ним в приватном репозитории компании, не в публичном форке.

**8. Первая неделя**

- Каждый разбор алерта — документ в базе. Через неделю у агента есть контекст.
- В пятницу — `kb-compile`.
- В конце большой задачи — `/retro`: что из правил мешало, чего не хватило.
- Перед публикацией правок в свой форк — `python3 scripts/check_sanitized.py` с новым стоп-листом.

## Если компания запрещает облачные модели

Harness не зависит от конкретной модели, но рассчитан на Claude Code и Codex. Если разрешены только внутренние
модели — правила, база знаний, `kb.py`, `kb_mcp.py` и журналы работают с любым агентом, который читает `AGENTS.md`
и поддерживает MCP; хуки придётся адаптировать под его формат событий.
