# kb-compile

Периодическая «компиляция» базы знаний `{{KB_ROOT}}` (git-репозиторий и Obsidian vault): журнал находок
(`findings/`) копится сам, а разделы «Состояние» в хабах (`services/<Name>.md`) устаревают, пока их не свернуть.
Каждый проход — один коммит, откат — `git revert`.

## 1. Что нового

`git -C {{KB_ROOT}} log --since="<дата последнего прохода>" --name-only -- findings incidents alerts duty tasks`
(дата — последний коммит «kb-compile» в `git log --oneline --grep kb-compile`). В `tasks/` читай журналы
(`handoff.md`: «Сейчас», «Сделано», «Грабли») и датированные итоги — в них часто самое свежее состояние сервиса,
а заметки по задаче не пишутся. Затем
`python3 {{HARNESS_HOME}}/tools/build_hubs.py`, чтобы списки заметок в хабах были свежими.

Готово, когда есть список новых заметок и для каждой понятно, к каким хабам она относится.

## 2. Состояние хабов

Для каждого затронутого хаба перепиши раздел «Состояние на <дата>»: только факты из заметок, у каждого пункта дата
и ссылка `[[имя-файла|заголовок]]` на источник. Факт, который новая заметка опровергает или заменяет, убери из
состояния; старой заметке добавь во frontmatter `superseded_by: <путь-новой-от-корня-базы>.md` (например
`findings/2026-10-16-….md`; у документа без frontmatter заведи его с `type`, `date`, `lifecycle: superseded`). Раздел остаётся срезом — пиши
его коротко, подробности живут в заметках.

Нового сервиса или тикета, на который ссылаются три и более заметок, ещё нет в хабах — создай хаб по образцу
существующего `services/<Name>.md` или `tickets/{{TICKET_EXAMPLE}}.md` (поле `hub_match` — regex по заголовку, тегам
и ссылкам).

Готово, когда каждый факт в «Состоянии» подкреплён заметкой не старше самой свежей по этой теме.

## 3. Решения и справка

Принятое решение (ADR, выбор схемы) или устойчивая справка («где лежит конфиг X») из находок переносится в
`{{KB_ROOT}}/decisions/` или `reference/` по правилам `{{KB_ROOT}}/AGENTS.md`, хаб ссылается туда.

## 4. Фиксация

`python3 {{HARNESS_HOME}}/tools/build_hubs.py`, затем закоммить только то, что изменил этот проход — хабы, помеченные
заметки, новые `decisions/`/`reference/`: `git -C {{KB_ROOT}} add -- <пути> && git -C {{KB_ROOT}} commit -m
"<KEY> kb-compile <дата>" -- <пути>`. Не `git add -A`: в базе лежат незаконченные правки параллельных чатов.
Без этого шага хук `Stop` закоммитит те же файлы с безликим сообщением `docs: …`.
Пользователю — какие хабы обновлены, что помечено superseded, что ушло в IaC/docs.
