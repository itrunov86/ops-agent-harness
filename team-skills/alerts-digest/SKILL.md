# Дайджест алерт-канала

Скилл даёт быструю сводку по каналу алертов за окно: что было, что повторялось, что не закрылось. Задача — вытащить
сигнал из шума, а не пересказать каждое сообщение. Скилл только читает; любые записи (задача, сообщение в чат) —
лишь предложение следующего шага.

Дефолты (каналы, окно, пороги, поля парсера) — в [`defaults.yaml`](./defaults.yaml).

## Когда применять

* «проверь алерты за день», «что в алертах за последние 6 часов»;
* «дайджест по <канал>»;
* утром на дежурстве — «что я пропустил».

Не применять:

* для одного алерта или инцидента — открой его тред (например, `mm_get_thread` или `mm_resolve_permalink`);
* для создания задач — [`tracker-story`](../tracker-story/SKILL.md);
* для каналов с обычной перепиской: парсер рассчитан на уведомления Alertmanager (или похожего источника).

## Настройка под команду

В `defaults.yaml`:

* `chat.team` — команда/workspace в чате;
* `chat.channels` — алерт-каналы, по умолчанию `{{ALERT_CHANNELS}}`; дайджест строится по первому, если
  пользователь не назвал другой;
* `parser.*` — под формат вашего шаблона уведомлений: какие жирные поля — это поля, а не имя алерта; какие эмодзи
  значат firing/warning/resolved; какие фразы — авто-тикеты. Сверь с двумя-тремя реальными сообщениями канала;
* `anomalies.*` — пороги flapping, «нездорового» namespace и всплеска.

Примеры инструментов ниже — для Mattermost; для другого чата возьми аналоги из MCP-сервера `{{MCP_HUB}}` или
попроси пользователя выгрузить сообщения.

## Шаги

### 1. Прочитай дефолты

Канал и окно из слов пользователя важнее дефолтов.

### 2. Найди канал

Нет id канала в этом разговоре — найди его по имени в списке каналов команды (например, `mm_list_channels`).

### 3. Забери сообщения за окно

* `since_ms = now_ms − window.hours × 3 600 000`.
* Первая страница — сообщения канала с `since_ms` (например, `mm_list_channel_posts`, `per_page` 200).
* Ответ говорит, что есть ещё — листай назад от самого старого полученного сообщения, пока страница не пуста, самое
  старое сообщение новее `since_ms` и не набрано `window.max_pages` страниц.
* Объедини и отсортируй по времени.
* Не используй поиск по сообщениям (например, `mm_search_posts`) для полного дайджеста: он режет результаты. Только
  для точечных вопросов.

### 4. Разбери сообщения

Для каждого сообщения:

* `status` — первое совпадение с `parser.status_emoji`;
* `alert_name` — первое жирное значение, которое не входит в `parser.field_names`;
* `severity`, `namespace`, `cluster`, `description` — значения после соответствующих жирных полей
  (`description` — только первая строка).

Класс:

* первая строка содержит маркер из `parser.ticket_markers` — `ticket` (авто-тикет), отдельная категория;
* нет ни эмодзи статуса, ни имени алерта — `chat` (люди в треде), в сводку не идёт;
* иначе — `alert`; имя не нашлось — `unparsed`, считай отдельной строкой и не угадывай.

### 5. Агрегируй

* объём: всего, алертов, тикетов, чата, unparsed;
* топ по имени алерта: количество, распределение статусов и severity;
* топ по namespace;
* распределение по severity;
* число авто-тикетов.

### 6. Найди аномалии

* **Flapping:** имя алерта встречается не меньше `anomalies.flap_threshold` раз; если firing не висит — явный
  flap.
* **Незакрытый firing:** последнее сообщение по имени (и месту) — firing, и после него нет resolved.
* **Нездоровый namespace:** не меньше `anomalies.unhealthy_namespace_distinct_alerts` разных имён алертов в одном
  namespace — проблема уже не в одном правиле.
* **Всплеск:** не меньше `anomalies.burst_count` алертов за `anomalies.burst_minutes` минут в скользящем окне.

### 7. Сводка

Markdown, не больше ~30 строк; секции аномалий — только если они есть:

```
## Алерты <канал> за <окно> (<от> → <до>)

**Объём:** N сообщений → M алертов (F firing, W warning, R resolved) + T авто-тикетов.

### Незакрытые firing
| Время | Алерт | Где | Кратко |

### Похоже на flapping
| Алерт | Раз | Severity | Где |

### Нездоровые namespace
| Namespace | Разных алертов | Имена |

### Всплеск
<время> — N алертов за Δ минут: <имена>

### Топ по типу
<top_alerts_rows строк: имя × количество, severity, статусы>

### Топ по namespace
<top_namespaces_rows строк>
```

При `behavior.use_tables: false` — списки `* Имя — количество, severity` вместо таблиц. Не выводи список тикетов
(хватает числа), хронологию каждого сообщения и человеческую переписку.

### 8. Предложи следующий шаг

1–2 строки и только предложение: для незакрытого firing — открыть его тред или поискать связанные задачи в
трекере; для flapping — завести задачу на настройку правила. Сам ничего не создавай и не пиши в чат без явного
подтверждения.

## Пример

Окно 24 ч, первый канал из `chat.channels`.

1. Канал найден, 40 сообщений, одна страница.
2. Разбор: 30 resolved, 3 firing, 2 warning, 4 тикета, 1 чат.
3. Аномалии: `HighRequestLatency` ×6 — flapping; `DiskUsageCritical` firing в 03:10 без resolved; namespace
   `payments` — 4 разных алерта; всплесков нет.
4. Сводка по шаблону и предложение: «открыть тред `DiskUsageCritical`? завести задачу на порог
   `HighRequestLatency`?».

## Чего не делать

* Не пересказывать алерты построчно.
* Не угадывать имя алерта.
* Не открывать треды каждого firing «на всякий случай» — только по просьбе.
* Не делать записей в трекер или чат без подтверждения.
* Не листать бесконечно — соблюдай `window.max_pages`.
