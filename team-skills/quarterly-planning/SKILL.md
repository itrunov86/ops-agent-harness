# Квартальная цель

Скилл оформляет инициативу как квартальную цель команды: сначала цель в вики, потом эпик и подзадачи в трекере.
Трекерную часть выполняет [`tracker-epic`](../tracker-epic/SKILL.md), чтобы настройки проекта и полей жили в одном
месте.

Файлы скилла:

* [`templates/quarter_page_init.wiki`](./templates/quarter_page_init.wiki) — заготовка новой страницы квартала;
* [`templates/goal_section.wiki`](./templates/goal_section.wiki) — секция одной цели;
* [`defaults.yaml`](./defaults.yaml) — пространство, страница-раздел, имя страницы квартала, пороги качества.

## Устройство страниц в вики

* Страница-раздел «Квартальное планирование» — короткое вступление и макрос дочерних страниц; ручные секции по
  кварталам туда не пишем.
* Дочерние страницы — по одной на квартал, имя по `wiki.quarter_page_title` (например, `Q2 2026`). Внутри —
  `h2.` с названием квартала и цели `h3. Цель N. <название>`, у каждой подсекции «Зачем», «Что появится к концу
  квартала», «Как поймём, что получилось», «Связанные задачи».

## Когда применять

* «оформи цель квартала про X»; «надо спланировать Q3»; «занеси в квартальное планирование цель про …».

Не применять для отдельного эпика ([`tracker-epic`](../tracker-epic/SKILL.md)), одиночной задачи
([`tracker-story`](../tracker-story/SKILL.md)), багов и инцидентов. Сомневаешься — спроси «это цель квартала или
просто эпик?».

## Настройка под команду

В `defaults.yaml`:

* `wiki.space` — по умолчанию `{{WIKI_SPACE}}`;
* `wiki.planning_page_id` — страница-раздел квартального планирования (пусто — спросить пользователя);
* `wiki.quarter_page_title` — шаблон имени страницы квартала;
* `wiki.quarter_label_pattern` — метка квартала для эпика и подзадач (например, `q2-2026`);
* `behavior.min_points_to_deliver`, `min_success_criteria` — минимумы качества цели;
* если квартал у вас не календарный — опиши сдвиг в `quarters.fiscal_start_month`.

## Шаги

### 1. Прочитай дефолты

Явные слова пользователя («это в Q3», «другое пространство») важнее.

### 2. Определи квартал

По сегодняшней дате: номер квартала `n = ((month − fiscal_start_month) mod 12) div 3 + 1`. При календарном годе
(`fiscal_start_month: 1`) месяцы 1–3 → Q1, 4–6 → Q2, 7–9 → Q3, 10–12 → Q4. Пользователь назвал другой квартал —
бери его.

### 3. Найди страницу квартала

1. Прочитай дочерние страницы раздела (например, `confluence_get_page_children`).
2. Страница квартала есть — прочитай её (например, `confluence_get_page`), чтобы видеть другие цели и не затереть их.
3. Нет — её создание из `templates/quarter_page_init.wiki` войдёт в черновик шага 5.

### 4. Сформулируй цель

Если пользователь принёс заметки встречи, используй их как опору, но перепиши связным деловым языком, а не
копируй.

* **Зачем** — 1–2 фразы о последствиях для бизнеса или команды, а не «нет процесса». Не «нет SLA», а «дежурный не
  понимает, насколько срочно браться за обращение, и из-за этого …».
* **Что появится** — артефакты с короткой расшифровкой, зачем каждый: «SLA на обращения — чтобы дежурный знал
  срочность».
* **Как поймём** — проверяемые критерии: числа, чек-листы, наблюдаемые сигналы.

Меньше `behavior.min_points_to_deliver` артефактов или `behavior.min_success_criteria` критериев — одно
компактное уточнение. Секцию «Что не входит» добавляй, только если пользователь явно попросил: она быстро
засоряется соседними темами.

### 5. Черновик и подтверждение

Номер цели — по числу существующих секций `h3. Цель` (новая страница — `Цель 1`). Заполни
`templates/goal_section.wiki`, покажи имя страницы, нужно ли её создать, и 5–10 строк секции. Спроси «записывать?».
Без явного «да» в вики ничего не пиши. Пропуск — только при `behavior.confirm_before_create: false` или постоянном
разрешении в конфиге пользователя.

### 6. Запиши цель

Создай страницу квартала, если её нет (например, `confluence_create_page`), и допиши секцию цели в конец (например,
`confluence_update_page` с добавлением; полная замена — только с сохранением остальных целей). Покажи ссылку и
спроси «идём заводить эпик?».

### 7. Эпик и подзадачи

Выполни шаги [`tracker-epic`](../tracker-epic/SKILL.md) начиная с черновика эпика. Передай:

* summary — `<тема цели>: <ключевые результаты>` (≤120 символов);
* описание по шаблону эпика; в «Ссылках» — прямая ссылка на страницу квартала, не на раздел;
* метки — стандартные `tracker-epic` + метка квартала;
* короткое имя эпика, если трекер его требует;
* подзадачи, если пользователь их перечислил; описание каждой — «Зачем → Что сделать → Что считаем готовым →
  Контекст».

### 8. Обратные ссылки на странице квартала

После создания эпика замени подсекцию «Связанные задачи» нужной цели:

```
h4. Связанные задачи

* *Эпик:* [<EPIC-KEY> — <summary>|{{TRACKER_URL}}/browse/<EPIC-KEY>]
* *Подзадачи:*
** [<KEY1>|{{TRACKER_URL}}/browse/<KEY1>] — <summary 1>
```

Прочитай текущее тело страницы, замени только этот блок внутри своей цели и сохрани страницу целиком. Это запись в
вики — назови её в черновике шага 7, чтобы одно подтверждение покрывало и её.

## Ответ пользователю

5–8 строк: страница квартала ссылкой, эпик ключом и summary, ключи подзадач одной строкой, отдельной строкой — что
не получилось. Цель не пересказывай.

## Пример

Пользователь приносит заметки встречи про дежурства: SLA, уровни критичности, ранбуки, приоритизация, глоссарий.

1. Квартал по дате — Q2; страница `Q2 2026` есть, целей на ней нет — это «Цель 1».
2. Формулировки: зачем — нет общего понимания «инцидент или плановая работа», нагрузка на дежурстве непредсказуема;
   что появится — глоссарий, SLA, уровни критичности, ранбуки на алерты, памятка дежурного; как поймём — у всех
   алертов есть ранбук, SLA согласованы, за месяц нет вопросов «что делать с этим алертом».
3. Черновик подтверждён, секция дописана. Эпик и пять подзадач созданы через `tracker-epic`.
4. В «Связанных задачах» Цели 1 — ссылка на эпик и список подзадач.

## Чего не делать

* Не копировать заметки встречи как есть.
* Не заводить эпик, пока цель не записана и не согласована в вики.
* Не дублировать дочерние страницы ручными секциями на странице-разделе.
* Не писать в вики и трекер markdown.
* Не использовать фамильярный тон: страницу читает вся команда.
* Не вписывать секреты, токены, внутренние адреса.
* Не затирать чужие цели при правке своей.
* Не создавать страницы будущих кварталов впрок.
