# Skill: duty-notes

Назначение — превращать реальные кейсы с дежурства (треды в Mattermost,
устные объяснения, инциденты без постмортема) в структурированные статьи
в Confluence, чтобы следующий дежурный нашёл ответ, а не звонил коллеге.

Шаблон статьи — [`templates/article.wiki`](./templates/article.wiki).
Дефолты (страницы Confluence, поведение) — в [`defaults.yaml`](./defaults.yaml).
**Никогда не правь шаблон/дефолты в рантайме — только через PR.**

## Когда применять

* «задокументируй кейс из треда»
* «запиши решение — как получить токен Centrifuge»
* «оформи в базу знаний: как перезапустить X»
* «добавь статью про Y»
* Вызывается вручную после любого нетривиального кейса на дежурстве.

Не применять для:

* Полноценных постмортемов (инцидент с таймлайном, action items) —
  используй [`postmortem`](../postmortem/SKILL.md).
* Плановых задач / Story — [`jira-planning-story`](../jira-planning-story/SKILL.md).
* Алертов с уже готовым ранбуком — просто обнови существующую страницу.

## Что делать (по шагам)

### 1. Прочитай дефолты

`defaults.yaml` содержит ID разводящей страницы (`index_page_id`) и space.
Не подменяй значения на лету.

### 2. Собери данные

**Если дана ссылка на Mattermost-тред:**
1. `mm_resolve_permalink(url)` — получи корневой пост.
2. `mm_get_thread(post_id)` — получи все реплики.
3. Прочитай тред и восстанови: что за проблема, как её решили, кто объяснил.
4. Если в треде есть скрины/вложения — отметь это в статье и попроси
   пользователя загрузить их в Confluence вручную (Mattermost API не даёт
   содержимое вложений через текущие tools).

**Если пользователь описывает кейс текстом:**
* Задай одно компактное уточнение, если не хватает симптома или решения.

### 3. Составь заголовок страницы

Коротко (3–7 слов), по сути кейса. Примеры:
* «Получение токена Centrifuge»
* «Pod в CrashLoopBackOff: нет секрета»
* «Grafana не грузит дашборд после апгрейда»

### 4. Отрендери статью по шаблону

Используй [`templates/article.wiki`](./templates/article.wiki). Заполни блоки:

* `{symptom}` — что видит дежурный: текст алерта, внешний признак, заявка.
* `{key_warning_title}` + `{key_warning}` — главная оговорка, которая
  спасёт от типичной ошибки (например: «не генерировать заново — взять из Vault»).
  Если очевидных ловушек нет — убери этот блок из статьи.
* `{diagnosis}` — пошаговые действия для понимания причины. Нумерованный список.
* `{solution}` — что делать по итогам диагностики. Нумерованный список.
* `{escalation}` — кому звонить и при каких условиях.
* `{links}` — ссылки: разводящая страница, Mattermost-тред, Grafana, Vault, etc.
* `{source}` — откуда взят кейс (например: «тред ops-private, разобрал
  Иван Петров»).

Все блоки — Jira/Confluence wiki markup:
* `h2.` для заголовков (не `#`);
* `*` и `**` для буллетов;
* `#` для нумерованных списков;
* `[label|url]` для ссылок;
* `{{...}}` для inline-кода;
* `{code:bash}...{code}` для блоков кода.

### 5. Покажи превью

Если `behavior.confirm_before_create: true` — покажи:
* заголовок страницы;
* структуру (перечисли блоки с первыми строками каждого);
* спроси «создавать?».

Если `false` — пропускай.

### 6. Создай страницу в Confluence

```
confluence_create_page(
  space=<confluence.space>,
  title=<заголовок>,
  parent_id=<confluence.index_page_id>,
  content=<отрендеренная статья>,
  content_format="wiki"
)
```

Запомни `id` и `url` созданной страницы.

### 7. Обнови разводящую страницу

Если `behavior.update_index_on_create: true`:

1. `confluence_get_page(page_id=<index_page_id>)` — прочитай текущее тело.
2. Найди таблицу «Статьи» (строки вида `|| Статья || Описание ||`).
3. Добавь строку: `| [<заголовок>|<url>] | <одна фраза о кейсе> |`.
4. `confluence_update_page(page_id=<index_page_id>, content=<обновлённое тело>)`.

Не трогай другие части разводящей страницы.

### 8. Верни результат

Коротко (3–5 строк):
* ссылка на созданную статью;
* ссылка на обновлённую разводящую страницу;
* если есть вложения в треде — напомни загрузить скрины вручную.

## Worked example

Пользователь: «вот тред [ссылка] — задокументируй кейс с токеном Centrifuge».

Скилл:
1. `mm_resolve_permalink(url)` → получает корневой пост.
2. `mm_get_thread(post_id)` → читает тред, восстанавливает: не генерировать,
   брать из Vault, один токен на все окружения.
3. Составляет заголовок: «Получение токена Centrifuge».
4. Рендерит статью по шаблону. В блоке «Важно» — «не генерировать заново».
5. Показывает превью, получает «да».
6. `confluence_create_page(parent_id="<ID страницы-оглавления>", ...)` → создаёт страницу.
7. `confluence_get_page("<ID страницы-оглавления>")` → читает разводящую, добавляет строку
   в таблицу «Статьи», `confluence_update_page(...)`.
8. Возвращает ссылки.

## Чего НЕ делать

* Не выдумывать шаги диагностики и решения — только то, что было в треде
  или сказал пользователь. Лучше оставить `{заполнить}`, чем сочинить.
* Не создавать страницу в другом space или под другим родителем без явной
  просьбы пользователя.
* Не использовать markdown в теле — только Confluence wiki markup.
* Не дублировать: если статья с таким названием уже есть (видно из
  разводящей или из истории чата) — предложи обновить существующую через
  `confluence_update_page`.
* Не вписывать в статью секреты, пароли, токены — только описание процесса.
* Не трогать содержимое других страниц, кроме разводящей и новой статьи.
