# Статья дежурства

Скилл превращает закрытый кейс с дежурства (тред в чате, устное объяснение коллеги, инцидент без постмортема)
в короткую статью в вики. Цель — чтобы следующий дежурный нашёл готовый ответ в базе, а не искал того, кто
помнит.

Файлы скилла:

* [`templates/article.wiki`](./templates/article.wiki) — структура статьи.
* [`defaults.yaml`](./defaults.yaml) — куда писать (пространство, раздел-оглавление) и поведение.

Шаблон и дефолты в рантайме не меняются: правка — обычным изменением репозитория.

## Когда применять

* «задокументируй кейс из треда»;
* «запиши решение — как выпустить новый сертификат для X»;
* «оформи в базу знаний: как перезапустить Y»;
* «добавь статью про Z»;
* после любого нетривиального кейса на дежурстве, по просьбе пользователя.

Не применять:

* для инцидента с таймлайном и задачами по недопущению — это [`postmortem`](../postmortem/SKILL.md);
* для плановой работы — [`tracker-story`](../tracker-story/SKILL.md);
* если у алерта уже есть ранбук — предложи дополнить существующую страницу.

## Настройка под команду

Заполни в `defaults.yaml`:

* `wiki.space` — пространство вики (по умолчанию `{{WIKI_SPACE}}`);
* `wiki.index_page_id` и `wiki.index_page_url` — страница-оглавление раздела статей: под ней создаются статьи, в её
  таблицу добавляются ссылки;
* `wiki.index_table_header` — шапка таблицы оглавления, если у вас другие колонки;
* `wiki.duty_page_url` — (необязательно) страница с регламентом дежурств для ссылок из статей.

Если `index_page_id` пуст, спроси пользователя, под какой страницей создавать статью, и предложи записать ответ в
дефолты.

## Шаги

### 1. Прочитай дефолты

Значения из `defaults.yaml` — контракт. Явные слова пользователя («положи в другое пространство») важнее дефолта.

### 2. Собери факты

Ссылка на тред в чате (`{{CHAT_URL}}/...`):

1. Разреши ссылку в корневой пост (например, `mm_resolve_permalink`).
2. Прочитай весь тред (например, `mm_get_thread`). Запасной путь — попроси пользователя вставить текст треда.
3. Восстанови: симптом, причину, что сделали, кто объяснил, какие были ловушки.
4. Вложения и скриншоты через API чата обычно недоступны: отметь их в статье и попроси пользователя загрузить их
   в вики вручную.

Описание текстом: если не хватает симптома или решения, задай одно компактное уточнение.

### 3. Придумай заголовок

3–7 слов о сути кейса, например «Под в CrashLoopBackOff: нет секрета», «Дашборд не грузится после обновления».

### 4. Заполни шаблон

Блоки [`templates/article.wiki`](./templates/article.wiki):

* `{symptom}` — что видит дежурный: текст алерта, внешний признак, обращение;
* `{key_warning_title}` и `{key_warning}` — главная ловушка, о которой стоит знать заранее (например, «не
  генерировать новый ключ — взять существующий из хранилища секретов»). Нет ловушки — убери весь блок;
* `{diagnosis}` — нумерованные шаги, чтобы понять причину;
* `{solution}` — нумерованные шаги исправления;
* `{escalation}` — к кому идти и при каких условиях;
* `{links}` — оглавление раздела, тред, дашборды, связанные статьи;
* `{source}` — откуда кейс (тред, дата, кто разобрал — с согласия пользователя).

Разметка — wiki markup вики/трекера, не markdown: `h2.` для заголовков, `*` и `**` для списков, `#` для
нумерованных, `[текст|url]` для ссылок, inline-код — текст в двойных фигурных скобках, блоки —
`{code:bash}...{code}`.

### 5. Покажи черновик и получи подтверждение

Запись в вики — внешняя запись. Покажи заголовок, родительскую страницу и блоки с первыми строками, спроси
«создавать?». Без явного «да» не создавай. Пропускать подтверждение можно, только если в `defaults.yaml`
`behavior.confirm_before_create: false` или конфиг пользователя даёт постоянное разрешение на такие записи.

### 6. Создай страницу

Создай страницу в вики (например, `confluence_create_page`) в пространстве `wiki.space`, родитель —
`wiki.index_page_id`, формат — wiki. Запомни id и URL. Без инструмента вики — отдай пользователю готовый текст для
ручной вставки.

### 7. Обнови оглавление

Если `behavior.update_index_on_create: true`:

1. Прочитай страницу-оглавление (например, `confluence_get_page`).
2. Найди таблицу статей и добавь строку `| [<заголовок>|<url>] | <одна фраза о кейсе> |`.
3. Сохрани страницу целиком (например, `confluence_update_page`), не трогая остальное содержимое.

Это вторая запись: она входит в подтверждение шага 5, только если ты явно назвал её в черновике.

### 8. Ответ пользователю

3–5 строк: ссылка на статью, ссылка на оглавление, напоминание про вложения, если они были.

## Пример

Пользователь: «вот тред — задокументируй, как перевыпустить клиентский сертификат для шлюза».

1. Тред прочитан: сертификат лежит в хранилище секретов, перевыпуск через пайплайн, после — перезапуск шлюза;
   ловушка — старый сертификат нельзя отзывать до раскатки нового.
2. Заголовок: «Перевыпуск клиентского сертификата шлюза».
3. Блок «Важно» — «не отзывать старый сертификат до раскатки нового».
4. Черновик показан, получено «да» — страница создана, строка добавлена в оглавление.

## Чего не делать

* Не придумывать шаги диагностики и решения: только то, что есть в треде или сказал пользователь. Лучше оставить
  `(заполнить)`, чем сочинить.
* Не создавать страницу в другом пространстве или под другим родителем без просьбы пользователя.
* Не писать тело в markdown.
* Не дублировать: статья с таким заголовком уже есть — предложи обновить её.
* Не вписывать секреты, пароли, токены и персональные данные — только описание процесса.
* Не менять другие страницы, кроме новой статьи и оглавления.
