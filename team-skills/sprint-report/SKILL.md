# Отчёт по спринту

Скилл создаёт страницу-снимок текущего спринта под разделом «Результаты спринтов» в вики: задачи из трекера с
разбивкой по статусам, связь с квартальными целями, закрытые задачи по исполнителям. Также закрывает спринт и
переносит незавершённые задачи в следующий.

Спринт определяется меткой задач `sprint-YYYY-wWW`, которую ставит [`tracker-story`](../tracker-story/SKILL.md).
Если ваша команда ведёт спринты на доске трекера, см. «Настройка под команду».

Файлы скилла:

* [`templates/sprint_page.wiki`](./templates/sprint_page.wiki) — страница снимка;
* [`templates/hub_table.wiki`](./templates/hub_table.wiki) — таблица спринтов на странице-разделе;
* [`defaults.yaml`](./defaults.yaml) — страницы вики, проект, параметры спринта, названия статусов.

## Когда применять

Создание или обновление снимка спринта, начало и закрытие спринта. Не применять для создания задач
([`tracker-story`](../tracker-story/SKILL.md)) и квартального планирования
([`quarterly-planning`](../quarterly-planning/SKILL.md)).

## Настройка под команду

В `defaults.yaml`:

* `wiki.space` (`{{WIKI_SPACE}}`), `wiki.sprint_hub_page_id` — раздел «Результаты спринтов»;
* `wiki.quarter_page_id` — страница текущего квартала из `quarterly-planning`; меняется при смене квартала. Пусто —
  колонка «Квартальная цель» не заполняется;
* `tracker.project_key` — по умолчанию `{{TRACKER_PROJECT}}`;
* `tracker.done_statuses`, `in_progress_statuses` — названия статусов вашего workflow;
* `tracker.active_sprint_label` — постоянная метка «в активном спринте», если используете;
* `sprint.source` — `label` (метки задач, как в `tracker-story`) или `board` (спринты доски трекера: тогда задачи
  берутся инструментами доски, например `jira_list_sprints` и `jira_sprint_issues`, а `sprint.board_id` нужно
  заполнить);
* `sprint.reference_start`, `cadence_weeks` — должны совпадать с `tracker-story`.

### 2. Определи спринт

Для `sprint.source: label`:

```
days         = (today − reference_start).days      # отрицательно, если раньше якоря
sprint_idx   = floor(days / (cadence_weeks × 7))
sprint_start = reference_start + sprint_idx × cadence_weeks × 7 дней
label        = "sprint-{год sprint_start}-w{ISO-неделя sprint_start, две цифры}"
period       = sprint_start … sprint_start + cadence_weeks × 7 − 1 дней
```

Пользователь назвал другой спринт — бери его. Для `board` — активный спринт доски.

### 3. Собери данные (параллельно)

* задачи спринта — поиск в трекере (например, `jira_search`) по
  `project = <project_key> AND labels = "<label>" ORDER BY priority DESC`, поля: ключ, summary, статус, исполнитель,
  приоритет; лимит 50, при большем числе — пагинация;
* квартальный план — страница `wiki.quarter_page_id` (например, `confluence_get_page`).

### 4. Сопоставь задачи с квартальными целями

Из страницы квартала извлеки пары «цель → эпик → подзадачи» (блоки «Связанные задачи»). Задача есть среди
подзадач цели — пиши `[Цель N: <название>|{{TRACKER_URL}}/browse/<EPIC-KEY>]`; нет — «—». Задача по смыслу близка
к цели, но не в списке — отметь «(по теме)» и спроси пользователя после создания страницы.

### 5. Черновик и подтверждение

Заполни [`templates/sprint_page.wiki`](./templates/sprint_page.wiki): название страницы `<label> · <период>`,
таблицы по статусам, покрытие целей, закрытые задачи по исполнителям. Сортировка: задачи — по приоритету, внутри —
по исполнителю; сводные таблицы — по убыванию числа задач.

Покажи название, итоговые числа и первые строки таблиц, перечисли записи (новая страница + строка в таблице
раздела) и спроси «публиковать?». Без явного «да» не пиши. Пропуск — только при
`behavior.confirm_before_create: false` или постоянном разрешении в конфиге пользователя.

### 6. Создай страницу снимка

Каждый вызов создаёт новую страницу (например, `confluence_create_page`) под `wiki.sprint_hub_page_id`; старые
снимки не перезаписываются — они история.

### 7. Обнови таблицу спринтов

Прочитай страницу-раздел и перезапиши таблицу по [`templates/hub_table.wiki`](./templates/hub_table.wiki) с новой
строкой сверху. Статус — «В работе», пока спринт активен.

## Закрытие спринта

«Закрой спринт», «подведи итоги»:

1. Сделай свежий снимок (статусы могли измениться).
2. В таблице раздела заполни «Завершено» (задачи в `tracker.done_statuses`) и смени статус на «Завершён».
3. Сними `tracker.active_sprint_label` с задач, которые не переносятся (например, `jira_update_issue`).

Шаги 2–3 — записи: перечисли задачи, которых коснёшься, и получи подтверждение одним черновиком.

## Начало нового спринта

«Начни спринт sprint-2026-w26»:

1. Закрой текущий (раздел выше).
2. Перенесённые задачи — с `active_sprint_label` и не в `done_statuses`; добавь им метку нового спринта.
3. Создай снимок нового спринта.

Массовое изменение меток — только после подтверждения списка задач.

## Ответ

3–4 строки: ссылки на снимок и раздел; «N задач в спринте, M связаны с квартальными целями, K вне целей»; один
вопрос, если есть спорные привязки.

## Чего не делать

* Не перезаписывать старые снимки.
* Не менять метки задач без подтверждения списка.
* Не писать в вики markdown.
* Не вписывать секреты и персональные данные сверх имён исполнителей, которые и так видны в трекере.
